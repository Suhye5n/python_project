# 카드뉴스 자동 디자인 스킬 — 인수인계 (클라우드 세션 → 로컬)

> 지금까지 **계획만** 세웠고 코드는 아직 없음. 로컬 세션에서 이 문서를 읽고 이어서 진행.

## 0. 지금 할 일 (로컬에서 바로 시작)
1. 레퍼런스 폴더 분석: `~/Desktop/카드뉴스 모음 0821~` (폴더별로 임의 분류되어 있음)
   - 폴더별 장수, 파일 형식, 이미지 크기(카드 규격) 현황 정리
   - 폴더마다 샘플 몇 장을 아래 "레퍼런스 분석 형식"으로 분석
   - 지금 폴더 구분보다 세밀한 **태그 체계 + 레이아웃 유형 8~12개** 초안 제안
   - 폴더 안에 성격이 섞인 경우, 폴더는 달라도 스타일이 같은 경우 짚어주기
2. 초안을 사용자가 확인한 뒤 전체 분석으로 진행
3. **아직 코딩하지 말 것** — 분석과 제안까지만

## 1. 목표
- 회사에서 카드뉴스를 자주 만듦 (홍보 대상: **책 / 제품 / 단톡방** 등, 분야가 매우 다양)
- 상위 스킬 `/cardnews`가 두 스킬을 이어서 실행
  - `cardnews-plan` (기획) — **다른 사람이 만듦**
  - `cardnews-design` (디자인) — **내가 만듦**
- 회사 사람들이 모두 공유해서 쓸 수 있어야 함

## 2. 결정된 방향
| 항목 | 결정 |
|---|---|
| 두 스킬 연결 | JSON 형식(`cardnews.json`)을 먼저 합의 → 각자 독립 개발 |
| 렌더링 | HTML/CSS 템플릿 → Playwright로 JPG. Claude는 JSON만 채움 (토큰 최소) |
| 스타일 선택 | 대화에서 1번 선택 (추천 + 선택지). 윤충희 팀장님 의견대로 결과물은 늘 이미지 |
| 스타일 레퍼런스 | 이미지는 **스타일 등록 때 1번만** 분석 → 텍스트 명세 + 템플릿으로 저장. 실행 때는 텍스트만 읽음 |
| 스타일 구조 | **레이아웃 유형(HTML 8~12개) × 테마(tokens.json: 색·폰트·여백)** — 템플릿 수를 고정 |
| 피그마 | 옵션. 스타일별 피그마 템플릿(레이어 이름 규칙: `headline`, `body`, `image_1`)을 복제해 내용만 교체. 처음부터 그리는 방식은 토큰이 많이 들어 비추천 |
| 이미지 | 스크립트가 API 호출 (Claude는 프롬프트/키워드만) |
| 공유 | 사내 Git 저장소 기반 플러그인. API 키는 저장소에 넣지 않음 (개인 `.env` → 장기적으로 사내 API 프록시) |
| 폰트 | 한글 폰트(Pretendard 등) 저장소에 포함, 라이선스 확인 |

## 3. 두 스킬을 잇는 JSON (초안)
```json
{
  "title": "2026 연말정산 바뀐 점 5가지",
  "promo_type": "책 | 제품 | 단톡방 | 기타",
  "domain": "자기계발",
  "tone": ["차분함", "신뢰"],
  "recommended_style": "clean-info",
  "cards": [
    {
      "type": "cover",
      "headline": "...", "sub": "...",
      "image": { "need": true, "kind": "photo", "query": "office tax documents", "prompt": null }
    },
    { "type": "body", "headline": "...", "body": "...", "image": { "need": false } },
    { "type": "outro", "cta": "..." }
  ]
}
```
`kind`: `photo`(실사) / `illustration`(일러스트) / `cartoon`(카툰) / `none`(없음)

## 4. 이미지 공급 규칙
| kind | 1순위 | 2순위 | 메모 |
|---|---|---|---|
| photo | Unsplash | Adobe Stock → 없으면 Gemini 생성 | Unsplash 가이드라인(출처, 다운로드 추적, 요청 한도) 준수 |
| illustration | Gemini | OpenAI | 스타일 톤 키워드를 프롬프트에 자동 추가 |
| cartoon | Gemini 또는 OpenAI + 캐릭터 레퍼런스 시트 | 다른 쪽 | 캐릭터 일관성이 핵심 |

- Adobe Stock은 라이선스 구매에 회사 크레딧이 차감되므로 "후보 제시 → 승인 시 구매"
- 실행당 생성 이미지 수 상한, 같은 프롬프트는 캐시로 재사용

## 5. 레퍼런스 라이브러리 (주제별 스타일 자동 매칭)
- 외부 SNS 자동 수집은 약관·차단 문제와 성과 데이터 부재로 어려움 → **수집은 사람이, 나머지는 자동**
- 흐름: 수집(폴더/노션/피그마 보드) → 이미지당 1회 분석해 JSON 저장 → 기획 결과로 검색 → 레이아웃 유형 + 테마로 적용
- 우리 카드뉴스는 `performance`(도달, 저장, 클릭, 단톡방 유입)를 기록 → 추천 정확도의 핵심 근거
- 실행 시: 후보 3개를 썸네일 한 장으로 보여주고 선택 또는 "알아서"
- 레퍼런스가 수백 장 넘으면 **이미지 임베딩 검색**(CLIP 등, Claude 토큰 0) 추가: 태그로 범위를 좁힌 뒤 임베딩으로 "느낌이 비슷한 것"을 고름. "이 느낌으로 해줘", 중복 정리, 스톡 사진 고르기에도 활용
- **모방의 선:** 레이아웃 구조, 배치 순서, 색 분위기, 폰트 계열, 훅 방식 같은 패턴만 따라 함. 외부 이미지·일러스트·캐릭터·로고·문구는 결과물에 절대 사용 금지 (분석용으로만)

### 레퍼런스 분석 형식 (이미지 1장당)
```json
{
  "id": "int-0001",
  "source": "internal | external",
  "file": "원본 경로",
  "promo_type": "책",
  "domain": "자기계발",
  "tone": ["차분함", "신뢰"],
  "layout_archetype": "big-quote",
  "palette": ["#1F2A44", "#F4EDE1", "#C8A15A"],
  "typography": "세리프 제목 + 산세리프 본문",
  "image_usage": "책 표지 목업, 하단 1/3",
  "text_density": "low | mid | high",
  "hook_pattern": "책 속 한 문장 인용",
  "performance": null
}
```

### 홍보 유형별 차이 (기획 스킬과도 공유)
| 유형 | 잘 먹히는 구성 | 디자인 포인트 |
|---|---|---|
| 책 | 책 속 문장 인용 → 핵심 내용 → 표지 + 구매 | 표지 목업, 여백, 세리프 |
| 제품 | 문제 제기 → 제품 단독컷 → 혜택/가격 → 구매 | 제품 사진 품질, 혜택 배지 |
| 단톡방 | 공감/희소성 → 얻는 것 → 참여 방법 | 강한 CTA, 링크/QR, 마감 강조 |

레이아웃 유형 후보: 큰 인용문형, 제품 단독컷형, 리스트형, 비교형, 대화/카툰형, 숫자 강조형, 공지/CTA형 …

## 6. 폴더 구조 (예정)
```
cardnews-plugin/
  skills/cardnews/           상위 스킬
  skills/cardnews-plan/      기획 (다른 분)
  skills/cardnews-design/    디자인
  skills/cardnews-add-style/ 스타일 등록 보조
  styles/<스타일>/  style.md, tokens.json, cover.html, body.html, outro.html, preview.jpg, refs/, character/
  references/  internal/, external/, index.json
  fonts/  scripts/  .env.example
```

## 7. 단계별 진행
1. **MVP:** JSON 형식 합의 → 스타일 1~2개 HTML 템플릿화 → JPG 렌더링 → 상위 스킬 연결. 이미지는 Unsplash만
2. Gemini/OpenAI 생성, 카툰 캐릭터 일관성, 스타일 등록 보조 스킬, 스타일 카탈로그 페이지, 레퍼런스 분석·매칭
3. 피그마 템플릿 교체 출력, Adobe Stock 승인 후 구매, 성과 데이터 연결
4. 사내 플러그인 배포, API 프록시, 사용량 대시보드, 이미지 임베딩 검색

## 8. 아직 정할 것
1. 회사가 쓰는 Claude 제품 (Claude Code / 데스크톱·Cowork / claude.ai 팀 플랜) → 배포 형태 결정
2. 카드 규격 (1080×1080, 1080×1350 등), 스타일마다 다른지
3. 현재 스타일 개수, 원본 피그마 파일이 있는지
4. Adobe Stock 회사 계정·크레딧, 생성 이미지의 상업적 사용 정책
5. API 키 관리 방식 (개인 / 중앙)
6. 기획 담당자와 JSON 형식 합의 일정
